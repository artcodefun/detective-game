# Detective Game — Спецификация

## 1. Концепция

Игрок — детектив, расследующий преступление (убийство/кража/etc). Каждая сессия генерируется LLM: уникальная история, 5 подозреваемых со своими воспоминаниями, мотивами и секретами. Игрок взаимодействует с ними через текст или голос, собирает факты, анализирует улики и сдаёт финальный отчёт.

## 2. Платформа и технологии

### MVP (на устройстве)

| Компонент        | Выбор                          |
| ---------------- | ------------------------------ |
| Фреймворк        | Flutter (Dart)                 |
| LLM              | DeepSeek API (прямые запросы)  |
| TTS/STT          | STT: `speech_to_text` (устройство). Озвучка: предсгенерированные аудио-ассеты (псевдоязык) |
| Изображения      | bundled assets (предсгенерированы) |
| Персонажи (пул)  | JSON в assets                  |
| Хранилище        | Hive (сохранение текущей сессии) |

### Продакшен (ближе к релизу)

| Компонент       | Изменение                                        |
| --------------- | ------------------------------------------------ |
| Изображения     | подтягиваются с бэкенда (не bundled)             |
| Персонажи (пул) | подтягиваются с бэкенда (можно обновлять без релиза) |
| LLM             | запросы через бэкенд-прокси (ключ не на клиенте)  |

## 3. Персонажи

- Всего в пуле: **50–100+ уникальных персонажей**
- Хранятся как **JSON-файл в assets** (MVP) — массив объектов
- Для каждого:
  - Имя, возраст, профессия
  - Изображение (AI-generated, **MVP**: bundled asset / **продакшен**: URL с бэкенда)
  - Краткое описание характера (2–3 предложения: темперамент, манеры речи, особенности)
  - ID аудио-тембра (для псевдоязыковой озвучки)
- В каждой сессии участвуют **5 персонажей**, выбранных случайно из пула
- Один из 5 — преступник (определяется LLM при генерации сценария)
- У каждого персонажа в рамках сценария:
  - Своя версия событий (частично правдивая)
  - Секреты, которые он не хочет раскрывать
  - Предубеждения, влияющие на показания
  - Отношения с другими персонажами
  - Отношение к детективу — динамическое, меняется в ходе допроса

## 4. Игровое пространство

### 4.0. Титульный экран (Title Screen)

- Три кнопки:
  - **Новое дело** → запуск генерации сценария (экран загрузки) → стол детектива
  - **Предыдущие дела** → список завершённых сессий (сохранены в Hive), можно посмотреть отчёт
  - **Настройки** → громкость звуковых эффектов, громкость музыки (пока базово)

### 4.1. Главный экран — «Стол детектива»

Центральный хаб. Содержит:

| Элемент                        | Описание                                         |
| ------------------------------ | ------------------------------------------------ |
| **Дело (Case File)**           | карточка с базовыми фактами → открывается как экран-документ |
| **Телефон**                    | открывает телефонную книгу со списком подозреваемых (карточки: портрет, имя, кнопка «Вызвать», счётчик оставшихся допросов) |
| **Улики (Evidence Locker)**    | просмотр собранных улик и результатов анализов |
| **Блокнот (Notebook)**         | хронология расследования + заметки (стилизация под записную книжку) |
| **Отчёт (Final Report)**       | написать итоговую версию → открывается экран-документ для написания, затем экран результатов |

Дизайн: стол с разложенными предметами (слева папка с делом, в центре блокнот, справа телефон и т.д.). Каждый предмет кликабелен.

### 4.2. Экран допроса (Interrogation Room)

- Переход из главного экрана при вызове персонажа
- Содержит:
  - Портрет и имя персонажа
  - Окно чата (текстовый ввод + кнопка голосового ввода через `speech_to_text`)
  - При каждой реплике персонажа проигрывается рандомный аудио-ассет с псевдоязыком (уникальный тембр для каждого персонажа)
  - При отправке вопроса детективом — похожий аудио-эффект (общий для детектива)
  - Индикатор настроения персонажа (визуальный: язык тела, выражение лица, тон ответов) — не числовой, игрок чувствует изменения по поведению:
    - **Открыт** (trust 75–100) → отвечает развёрнуто, доброжелателен
    - **Сдержан** (trust 50–74) → короткие ответы, избегает деталей
    - **Напряжён** (trust 25–49) → огрызается, переводит тему
    - **Закрыт** (trust 0–24) → отказывается отвечать, просит закончить допрос
  - Внутри системы: числовое отношение к детективу (0–100), игроку не показывается:
    - LLM сама решает, как ответ игрока влияет на отношение, и возвращает дельту в JSON-ответе
    - Скорость изменения зависит от характера персонажа
- Игрок задаёт вопросы текстом или голосом
- LLM получает: полную историю диалога + CharacterState персонажа
- LLM возвращает структурированный JSON:
  ```json
  {
    "answer": "текст ответа от лица персонажа",
    "attitude": -10,
    "statements": ["я был дома в 12:00", "почему вы вообще меня спрашиваете?"]
  }
  ```
  - `attitude` — дельта для внутреннего trust (положительное или отрицательное)
  - `statements` — список ключевых утверждений, авто-сохраняемых в блокнот
- Допрос заканчивается: по времени (лимит **10 минут**) или нарративно — персонаж устал, начинает отвечать односложно, просит завершить
- При повторном допросе: чат визуально начинается заново (чистое окно), но в промпт передаётся полная история всех предыдущих допросов с этим персонажем — он помнит, о чём говорили
- В любой момент можно завершить допрос и вернуться к столу

### 4.3. Хранилище улик (Evidence Locker)

- Все вещественные улики выдаются в начале сессии (собраны экспертами на месте преступления)
- Новые улики по ходу игры не появляются
- Сетка улик (карточки с названием, иконкой, кратким описанием)
- Клик по улике → открывается **экран-документ** с детальным описанием
- Кнопка «Анализировать» → выбор типа анализа (ДНК, отпечатки, хим. анализ), трата 1 очка действия → результат открывается как новый документ
- Также очки действий можно потратить на проверку алиби и запрос данных (камеры, транзакции) — через соответствующие кнопки в интерфейсе

### 4.4. Экран блокнота (Notebook)

- Стилизован под записную книжку: жёлтый фон, линовка
- Две вкладки:
  - **Хронология (Timeline)**: лента всех событий в деле
    ```
    12:40 — Допрос подозреваемого (Майкл)
    12:52 — Допрос подозреваемого (Елена)
    13:22 — Результат анализа ДНК (Нож)
    13:45 — Допрос подозреваемого (Майкл, повторный)
    ```
    Каждый пункт кликабелен → раскрывается детальный вид внутри блокнота (перелистывание страницы)
  - **Заметки (Flagged)**: только реплики и события, помеченные игроком как «странно» / «подозрительно» / «ключевое»
- Внутри детального вида допроса: реплики можно помечать (странно/подозрительно/ключевое)

### 4.5. Экран документа (Document Viewer)

- Универсальный просмотрщик, используется для:
  - Папка дела (Case File) — общая информация: тип преступления, дата, место, список подозреваемых, brief
  - Описание улики
  - Отчёт лаборатории (результат анализа)
  - Банковская выписка / телефонные записи / записи с камер
  - Финальный отчёт (перед отправкой)
- Стилизован под официальный документ/бланк (белый фон, печатный шрифт)
- Единый компонент, разные данные
- Это ключевая механика — именно так детектив находит ложь

## 5. Состояние игры (Game State)

**Архитектурный принцип**: игра владеет всем состоянием мира в структурированном виде (JSON). LLM используется **только** для генерации естественного языка и поведения персонажей. Состояние не хранится в промптах — LLM читает JSON, но не меняет его.

### 5.1. Структуры данных

```dart
class GameSession {
  final String id;
  final Crime crime;           // что произошло (ground truth)
  final Timeline timeline;     // хронология событий
  final List<Evidence> evidence;   // все улики (выданы на старте)
  final List<CharacterState> characters; // персонажи в этой сессии
  final List<NotebookEntry> timeline_log; // действия игрока
  final int actionPoints;      // оставшиеся очки действий
}

class CharacterState {
  final CharacterData base;    // статичные данные (имя, портрет, характер)
  final CharacterKnowledge knowledge; // что персонаж знает
  final List<String> secrets;  // что скрывает
  final Map<String, String> relationships; // отношение к другим персонажам
  final List<Memory> memories; // ключевые воспоминания (read-only для LLM)
  final int trust;             // отношение к детективу (скрыто от игрока)
  final int interrogationsRemaining; // осталось допросов
}

class CharacterKnowledge {
  final List<String> knownFacts;      // что персонаж точно знает
  final List<String> partialFacts;    // что знает частично / неточно
  final List<String> falseBeliefs;    // в чём заблуждается
}

class Memory {
  final String id;
  final String content;        // «Я видел Джона в баре в 20:00»
  final bool isTrue;           // правда или ложь (относительно ground truth)
  final String timestamp;      // игровое время события
}
```

### 5.2. Роль LLM

| Функция                        | Кто делает          |
| ------------------------------ | ------------------- |
| Хранение фактов, улик, таймлайна | **Игра** (JSON)     |
| Хранение знаний персонажей     | **Игра** (JSON)     |
| Оценка финального отчёта       | **Игра** (сравнение с ground truth) + LLM (нарративный фидбек) |
| Ответ от лица персонажа        | **LLM** (читает CharacterState → генерирует реплику) |
| Генерация сценария             | **LLM** (конвейер, см. ниже) |
| Нарративный фидбек             | **LLM**             |

## 6. Игровая механика

### 6.1. Основной цикл

```
Новое дело → генерация сценария (конвейер LLM, экран загрузки)
  → изучение дела (Case File)
  → допрос персонажей (можно вызывать повторно)
  → анализ улик, проверка алиби (трата очков действий)
  → написание финального отчёта
  → оценка (игра + LLM) → экран результатов → конец сессии
```

### 6.2. Генерация сценария (конвейер)

Не один большой промпт, а последовательность шагов. Каждый шаг — отдельный вызов LLM с чётко определённым входом/выходом:

```
1. Crime
   Вход: 5 персонажей
   Выход: тип преступления, жертва, преступник, мотив, способ

2. Timeline
   Вход: Crime + персонажи
   Выход: хронология (кто где был в какое время)

3. Evidence
   Вход: Crime + Timeline
   Выход: список улик, их расположение, к кому ведут

4. Witness Memories
   Вход: Crime + Timeline + Evidence + персонажи
   Выход: для каждого персонажа — CharacterKnowledge (что знает, что скрывает, в чём заблуждается)

5. Consistency Check
   Вход: все предыдущие выходы
   Выход: проверка на логические дыры → если есть → возврат на шаг 2 или 3
```

Плюсы конвейера:
- Каждый шаг можно отлаживать и заменять независимо
- При смене модели (DeepSeek → другая) архитектура не меняется
- Провалившийся consistency check не требует перегенерации всего сценария

### 6.3. Очки действий (Лупа)

- Единый ресурс на всю сессию: **5 очков действий** (лупа / жетоны)
- Потратить можно на следующие действия:

  | Действие                              | Стоимость | Результат                                        |
  | ------------------------------------- | --------- | ------------------------------------------------ |
  | Анализ ДНК                            | 1 очко    | точный или частичный факт об улике               |
  | Поиск отпечатков                      | 1 очко    | подтверждение/опровержение причастности персонажа|
  | Химический анализ                     | 1 очко    | состав вещества, время, происхождение            |
  | Проверка алиби                        | 1 очко    | подтверждение или опровержение алиби персонажа   |
  | Запрос записи с камер / банковских транзакций | 1 очко | перемещения персонажа в интересующее время       |

- Каждое действие может дать: **точный факт**, **частичный факт** или **ничего** (зависит от релевантности)
- Потраченные очки не восстанавливаются
- Игрок может проиграть по очкам, если исчерпает все действия и не соберёт достаточно доказательств

### 6.4. Ограничения на допросы

- Каждого персонажа можно вызывать на допрос **до 3 раз**
- Один допрос длится максимум **10 минут** или до нарративного завершения
- Противоречия, обнаруженные позже, — повод для повторного вызова

## 7. Завершение игры

### 7.1. Финальный отчёт

Игрок в свободной форме пишет свою версию событий. Обязательные пункты для освещения:

1. **Кто** совершил преступление
2. **Почему** (мотив)
3. **Как** (способ)
4. **Когда** (время)
5. **Улики**, подтверждающие версию

### 7.2. Оценка

- **Игра** сравнивает ответы игрока с ground truth (JSON) по каждому из 5 пунктов → бинарно correct/incorrect
- **LLM** получает отчёт игрока и ground truth → генерирует нарративный фидбек и пояснения
- LLM возвращает JSON:
```json
{
  "narrative_feedback": "Вы верно определили преступника, но ошиблись в способе...",
  "breakdown_details": {
    "who": "Вы правы, это был Майкл.",
    "why": "Верно, мотив — финансовая махинация.",
    "how": "Нет, орудие — нож, а не яд, как вы предположили.",
    ...
  }
}
```
- Итоговый accuracy считается игрой: correct / 5 * 100%

### 7.3. Экран результатов

- Процент точности (0–100%)
- Разбор по каждому из 5 пунктов: ✓ или ✗ с пояснением
- Список упущенных важных фактов
- Краткий нарративный фидбек (1–2 предложения)
- Кнопка «Новое дело» → новая сессия

### 7.4. Предыдущие дела

- Список завершённых сессий (из Hive)
- Клик → просмотр финального отчёта и результатов
- Только чтение, переиграть нельзя

| Параметр                | Значение                                          |
| ----------------------- | ------------------------------------------------- |
| Язык                    | Русский                                           |
| Сеть                    | Онлайн-only (нет интернета → блокирующий диалог)  |

## 9. LLM-промпты (концептуально)

### 8.1. Генерация сценария (конвейер)

Каждый шаг конвейера — отдельный вызов с чётким JSON-входом и JSON-выходом. Пример для шага Crime:

**Вход:**
```json
{
  "characters": [ { "name": "...", "personality": "..." }, ... ]
}
```

**Выход:**
```json
{
  "crime_type": "murder",
  "victim": "Robert Lang",
  "perpetrator_id": "char_03",
  "motive": "financial fraud cover-up",
  "method": "poisoning",
  "time_of_crime": "22:15"
}
```

Аналогично — остальные шаги. Главное: каждый выход валидируется игрой на соответствие схеме, прежде чем идти дальше.

### 8.2. Ответ персонажа на допросе

**Вход (каждый запрос):**
- Полная история диалога с этим персонажем (включая предыдущие допросы)
- `CharacterState` персонажа (knowledge, secrets, memories, текущий trust)
- Последнее сообщение игрока

**Выход (JSON):**
```json
{
  "answer": "текст ответа от лица персонажа",
  "attitude": -10,
  "statements": ["я был дома в 12:00", "почему вы меня спрашиваете?"]
}
```

Правила для LLM (передаются в системном промпте):
- Не выдумывай факты, отсутствующие в knowledge/memories
- Не раскрывай секреты без веской причины (улика, давление)
- Сохраняй внутреннюю непротиворечивость со всей историей диалога
- Реагируй на тон игрока согласно характеру и уровню trust
- `attitude`: положительное, если игрок вежлив/эмпатичен; отрицательное — если давит/обвиняет
- `statements`: 1–3 ключевых утверждения из ответа для сохранения в блокнот

### 8.3. Нарративный фидбек (оценка)

Генерирует качественный отзыв на основе сравнения отчёта игрока с ground truth. Бинарное correct/incorrect считает игра, LLM даёт только пояснения.

## 10. Валидация сценария (игра)

После конвейерной генерации игра сама проверяет целостность:
- У каждого персонажа есть мотивация (даже у невиновных)
- Таймлайн не содержит дыр (все ключевые моменты покрыты)
- Улик достаточно для раскрытия (минимум 2 неопровержимых)
- Сценарий раскрываем, но не тривиально

## 12. Принятые решения (из открытых вопросов)

| Вопрос                                                | Решение                                               |
| ----------------------------------------------------- | ----------------------------------------------------- |
| STT (голосовой ввод)                                  | `speech_to_text` на устройстве                        |
| Озвучка персонажей                                    | **Без TTS**. Предсгенерированные аудио-ассеты с псевдоязыком (разные тембры для каждого персонажа + детектив, ~10 на персонажа, рандомно при репликах) |
| Локации                                               | Только стол детектива и допросная. Остальное — экраны-документы |
| Экран блокнота                                        | Стилизован под записную книжку (жёлтый фон, линовка). Вкладки: «Хронология», «Заметки» |
| Экран документа                                       | Универсальный просмотрщик для: описание улики, отчёт лаборатории, банковские выписки, телефонные записи, папка дела |
| Папка дела (Case File)                                | Тоже экран-документ с общей информацией о деле        |
| Место преступления                                    | Отдельного экрана нет — нечего там делать              |
| Персонажи (формат хранения)                           | **MVP**: JSON-файл в assets со всеми 50+ персонажами (имя, характер, портрет) |
| Тёмная тема                                           | Пока нет                                               |
| Планшеты / адаптив                                    | Только портретная ориентация, без адаптации            |
| Туториал                                              | Нет, ставка на интуитивный UI                          |
| State management                                      | **BLoC**                                               |
| Сеть                                                   | Онлайн-only. Без интернета — блокирующий диалог        |
| Язык                                                   | Русский                                                |
| Уровни сложности                                       | Нет (всегда одна сложность)                             |
| Улики                                                  | Все вещественные улики выдаются на старте. Новых не появляется |
| История диалога в LLM                                  | Полная (все допросы персонажа, без усечения)            |
| LLM-ответ на допросе                                   | JSON: `answer`, `attitude`, `statements`                |
| Trust                                                  | 0–100, маппинг: 75+=открыт, 50-74=сдержан, 25-49=напряжён, 0-24=закрыт. LLM возвращает дельту |
| Авто-сохранение в блокнот                              | LLM возвращает список `statements` → игра сохраняет     |
| Повторный допрос                                       | Чат заново визуально, история передаётся в промпт (персонаж помнит) |
| Телефон                                                | Телефонная книга: карточки с портретом, именем, кнопкой вызова, счётчиком оставшихся допросов |
| Титульный экран                                        | «Новое дело», «Предыдущие дела», «Настройки»            |
| Экран загрузки                                         | Да, пока работает конвейер генерации сценария           |
